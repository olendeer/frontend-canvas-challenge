# Канвас генераций

Редактор цепочек «текст → генератор → результат» на React Flow: пространства, ноды, связи,
автосохранение графа через REST и тестовая генерация изображения.
Next.js 16 (App Router), TypeScript, TanStack Query.

Условия: [задание](../../docs/ASSIGNMENT.md) · [интеграция](../../docs/INTEGRATION.md) ·
[критерии](../../docs/EVALUATION.md).

## Запуск

Из корня репозитория, после `npm ci`, в двух терминалах:

```sh
npm run dev        # бэкенд, http://localhost:4001
npm run dev:web    # фронтенд, http://localhost:3000
```

Адрес API берётся из `NEXT_PUBLIC_API_URL`. Если бэкенд поднят на другом порту, скопируйте
`apps/web/.env.example` в `apps/web/.env.local` и поправьте значение.

```sh
npm run build:web       # сборка
npm run start:web       # запуск собранного
npm run typecheck:web   # tsc --noEmit
npm run test:web        # юнит-тесты (vitest)
npm run e2e:web         # сквозные сценарии (playwright)
```

Для e2e один раз нужен `npx playwright install chromium` — API и фронтенд Playwright поднимает
сам. Проверялось на Node 20.20 и npm 11.14.

## Как устроено

Слои лежат в `src/`, зависимости направлены внутрь: `core → data → domain → features`.

```
core/      HttpClient, HttpError, Endpoint, журнал идемпотентности, хранилище;
           adapters/fetch — единственное место с fetch во всём приложении;
           sync/ — WriteQueue, store/ — ObservableStore под useSyncExternalStore
data/      endpoints.ts — единственное место с адресами; репозитории и dto/
domain/    без React: graph/ (правила и версии), generation/, errors/, config/
query/     кэш серверного состояния: <область>/*.queries.ts, ключи, клиент
features/  экраны: *.module.tsx + *.hooks.ts — canvas/, spaces/, error-alert/
ui-kit/    Button, Field, TextArea, Select, Alert, StatusBadge, Card, …
```

Поток данных: `страница → модуль фичи → *.hooks.ts → useXxxService() → доменный сервис →
репозиторий → HttpClient`. Компонент в сеть не ходит и ответ не разбирает: он получает готовые
данные или текст ошибки через `getErrorMessage(error)`.

### Работа с API

Весь обмен идёт через `FetchAdapter`. Он собирает заголовки (`Accept`, `Content-Type`,
`If-Match`, `Idempotency-Key`), сериализует тело, проверяет статус, разбирает JSON с учётом
ответов без тела (204 и 304) и вытаскивает `ETag`, `Location`, `Retry-After`, `X-Request-Id`.
Наружу выходит либо `HttpResponse<TData>`, либо `HttpError` — сетевая, HTTP- и ошибка разбора
приведены к одному виду в одном месте. Адреса живут в `data/endpoints.ts`, конверт ошибки
разбирает `ApiErrorDto`, текст для пользователя берётся из таблицы кодов
в `domain/errors/error-message.ts`.

`GraphServiceImpl` держит `Map<spaceId, ETag>`: `read` кладёт туда ETag из ответа, `save` сам
подставляет его в `If-Match` и сохраняет новый. Если версии почему-то нет, `save` сначала
читает граф, поэтому `428 PRECONDITION_REQUIRED` не может случиться. `IdempotencyJournal`
хранит в `localStorage` пару «намерение → ключ + отпечаток тела», поэтому потерянный ответ
не создаёт вторую генерацию даже после перезагрузки.

### Debounce и очередь сохранений

`WriteQueue` в `core/sync` не знает про граф: ему передают паузу, функцию чтения тела и функцию
записи. Правка перезапускает таймер на `debounceMs` из `GET /api/config`, поэтому серия быстрых
правок даёт один PUT. Тело читается **в момент отправки**, так что уходит самое свежее
состояние. Пока запрос в полёте, новые правки только помечаются — параллельного PUT одного
графа не бывает. Ответ в черновик не пишется, из него берётся только ETag, поэтому старый ответ
не может затереть свежие правки. `flush()` вызывается перед генерацией и учитывает и
несработавший debounce, и запрос в полёте. Автоповтора после ошибки нет — иначе при
недоступной сети получился бы цикл; `412 GRAPH_VERSION_CONFLICT` останавливает очередь до
кнопки «Перечитать граф».

### Разбор участка: проверка связи при перетаскивании

React Flow вызывает `isValidConnection` на каждом кадре жеста и для каждого порта под
курсором — десятки вызовов в секунду. Проверить нужно четыре условия: совместимость типов,
занятость входа, наличие результата у генератора, петлю. Прямая реализация на массивах — это
`find` дважды и `some` дважды, то есть четыре линейных прохода на вызов.

`buildGraphIndex` собирает индекс за **два прохода** (один по нодам, один по связям) в четыре
`Map` с примитивными значениями: тип ноды, текст, источник занятого входа, результат
генератора. После этого проверка — четыре обращения к `Map` и ноль аллокаций на вызов; тем же
индексом пользуется `getChainIssue`, повторяющий серверную проверку `INCOMPLETE_CHAIN`.

Индекс пересобирается только при изменении структуры или данных нод. Перетаскивание
(`position`), выделение (`select`) и замер (`dimensions`) его не трогают — прежняя ссылка
переезжает в новый снимок, поэтому перетаскивание 20 нод при 60 кадрах в секунду не делает ни
одного лишнего прохода. По памяти индекс держит только примитивы: удалённые ноды он от сборки
мусора не удерживает.

## Проверенные сценарии

`npm run e2e:web` — 15 сценариев в браузере, все проходят: создание пространства и трёх типов
нод, допустимые и запрещённые связи, удаление ноды вместе со связями, серия правок одним PUT,
отсутствие наложения PUT при медленном ответе, конфликт версий с «Перечитать граф», генерация
сразу после правки, восстановление после перезагрузки во время генерации, тестовый отказ
с повтором, двойное нажатие кнопки генерации, потерянный ответ на запуск, остановка опроса
после завершения, защита от подстановки результата в чужую ноду, сохранение положения канваса,
удаление клавишей Delete и проход с клавиатуры на ширине 1280.

`npm run test:web` — 31 юнит-тест: поведение `WriteQueue`, правила графа, правила генераций,
разбор ошибки API и журнал идемпотентности.

## Недоработки

- Сценарий генерации — локальное состояние ноды: схема графа его не хранит, после перезагрузки
  сбрасывается на «Успех».
- Связи создаются только перетаскиванием, с клавиатуры их не соединить.
- Слияния версий при конфликте нет — только «оставить черновик» или «перечитать граф».
- Серверный граф не перечитывается в фоне: правка из другой вкладки видна только на следующем
  сохранении, ответом 412.
- Нет отмены действий, истории, копирования нод, зума картинки и тёмной темы.
- Юнит-тестами покрыты правила и очередь записи, но не React-компоненты.
- Мобильная раскладка канваса не делалась — по заданию она не оценивается.
